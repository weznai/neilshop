# 指甲电商独立站 · 业务功能完善度分析（v1.2）
> 对照 Shopify 标准店 + Glamnetic/Olive & June 等 DTC 标杆，逐环节审计现有设计（12 前台 + 9 后台模块），补齐缺口。

---

## 1. 审计结论总览

| 环节 | 现有覆盖 | 缺口等级 | 结论 |
|---|---|---|---|
| 商品 | ✅ 良好 | 🟡 中 | 缺：尺码 guide、预售、多规格图 |
| 购物/结算 | ✅ 良好 | 🔴 高 | 缺：多种支付方式、税费展示、地址校验、购物车营销 |
| 订单履约 | ⚠️ 基础 | 🔴 高 | 缺：物流跟踪、拆单发货、换货、时效承诺 |
| 会员资产 | ⚠️ 基础 | 🔴 高 | 缺：订阅制、礼品卡、储值、生日营销 |
| 营销转化 | ⚠️ 基础 | 🔴 高 | 缺：订阅弹窗分层、推荐有礼、闪购、EXIT intent |
| 客服售后 | ❌ 薄弱 | 🔴 高 | 缺：工单、退换货流程、FAQ、客服工作台 |
| 数据运营 | ⚠️ 基础 | 🟡 中 | 缺：商品运营(上架表现)、库存周转、LTV |
| 合规信任 | ❌ 薄弱 | 🔴 高 | 缺：GDPR 全套、Cookie 同意、年龄、邮件退订中心 |
| 供应链 | ❌ 缺失 | 🟡 中(P1) | 缺：采购、在途、成本毛利 |

**总体判断**：现有设计覆盖了"能下单"的主干，但按 DTC 品牌运营标准，**售后/合规/会员深度运营**三块是明显短板，且多数属于 P0/P1 就必须有的（否则上线即踩坑）。

---

## 2. 逐模块缺口清单与补齐方案

### 2.1 商品域

| 缺失功能 | 说明 | 优先级 |
|---|---|---|
| 甲型/尺寸指南 | 穿戴甲核心痛点：怎么量甲床、选尺码。需交互式 guide（对照卡+测量教程页+详情页弹窗），**直接影响退货率** | P0 |
| 变体级图片 | 不同甲型/色号各自图片，选择变体切换Gallery | P0 |
| 预售/缺货登记 | 爆款断货时"到货通知我"（Klaviyo back-in-stock 流），白白流失流量太可惜 | P1 |
| 商品视频 | 佩戴过程短视频（转化率高于图） | P1 |
| 多语言商品信息 | product_translations 表（title/desc 按locale） | P2 |
| 组合商品(套装) | 已有 bundle 基础，补"套装"作为独立商品形态 | P1 |
| 上架时间/定时上架 | published_at 已有，补后台定时任务 | P1 |

**补 DDL**
```sql
CREATE TABLE variant_images(variant_id, image_url, sort_order);       -- P0
CREATE TABLE stock_notifications(id, variant_id, email, notified_at,  -- P1 到货订阅
  UNIQUE(variant_id, email));
CREATE TABLE product_translations(product_id, locale, title, subtitle,
  description_md, UNIQUE(product_id, locale));                        -- P2
```

### 2.2 交易域（缺口最大，逐项补）

| 缺失功能 | 说明 | 优先级 |
|---|---|---|
| **支付方式矩阵** | 只有 Stripe 卡支付。北美必备：**PayPal**(20%+)、Apple/Google Pay(Stripe 自带开)、Klarna/Afterpay **先买后付**（美妆高客单转化利器，客单$30+建议必上） | P0 |
| 税费计算与展示 | 美国各州销售税（Stripe Tax 一行接入）；欧盟 VAT 展示价含税；结账页拆分行(subtotal/shipping/tax/total) | P0 |
| 地址校验 | Smarty/Google 地址自动补全+纠错，省运费纠纷 | P1 |
| 购物车挽留 | 购物车页展示"库存仅剩X"、免邮进度条(已有)、推荐搭配(已有 bundle)补：**限时保留提示**（30min 保留，超时释放——正好复用库存预扣机制） | P1 |
| 礼品卡/礼品选项 | 礼品卡(数字码)是 DTC 大杀器(节日季)；订单礼品留言+隐藏发票价格 | P1 |
| 订单备注 | 下单留言字段（已有 note 字段，补前台入口） | P0 |
| 发票 | 欧盟 B2B 需要 VAT 发票；美国收据即可（邮件收据已有） | P2 |
| 多币种结算 | 展示币种(M12)已有；补 PayPal 多币种账户说明 | P2 |

**补 DDL**
```sql
CREATE TABLE gift_cards(id, code, balance, initial_amount, status,     -- P1
  purchased_by_order_id, expires_at);
CREATE TABLE gift_card_ledger(id, gift_card_id, order_id, change, balance_after);
CREATE TABLE payment_methods(id, order_id, method,                     -- P0 拆分支付
  provider(enum: stripe/paypal/klarna), amount, status);               -- 卡+礼品卡组合
```

### 2.3 订单履约与物流（现有最薄弱之一）

| 缺失功能 | 说明 | 优先级 |
|---|---|---|
| **物流跟踪页** | Shippo Webhook 更新状态已有钩子，缺：用户侧 /track 页展示轨迹时间线、异常件(滞留/失败)标红+客服介入工单 | P0 |
| **拆单发货** | 一单多包(甲片+睫毛分仓)、部分发货多次回填运单号：shipments 表 | P1 |
| **换货流程** | 美妆 DTC 常态"不喜欢免费换"：换货单(exchange)关联原单，重发不回收（成本低体验好） | P1 |
| 退换货自助门户 | 用户侧提交退货申请(选原因)→RMA 号→预付标签(Shippo)→退款；后台 RMA 审核 | P0 |
| 时效承诺展示 | 详情页/结算页显示"预计 X-Y 天送达"(按承运区域规则) | P1 |
| 物流商规则 | 按重量/目的国/金额自动选承运(USPS/UPS/DHL)，运费表配置化 | P1 |
| 海关/报关 | 国际件 CN22/商业发票(客单低可走 USPS 简易报关) | P2 |

**补 DDL**
```sql
CREATE TABLE shipments(id, order_id, tracking_no, carrier, label_url,   -- P1 拆单
  status, shipped_at, delivered_at);
CREATE TABLE returns(rma_no, order_id, order_item_id, qty, reason,     -- P0 RMA
  status(enum: requested/approved/in_transit/received/refunded/rejected),
  label_url, refund_amount, created_at);
CREATE TABLE exchanges(id, order_id, order_item_id, new_variant_id,    -- P1
  status, tracking_out);
CREATE TABLE shipping_rates(id, dest_country, carrier, method,         -- P1 运费规则
  min_weight, max_weight, price, eta_min_days, eta_max_days, active);
```

### 2.4 会员与留存（DTC 的命脉，缺口大）

| 缺失功能 | 说明 | 优先级 |
|---|---|---|
| **订阅制(美甲月盒)** | glamnetic 无此业务但 Oh Color/Dashing Diva 有：订阅频次(4/6/8周)自动扣款+专属折扣，LTV 翻倍利器。Stripe Billing | P2(战略级) |
| 储值/钱包 | 充值送(充$50送$5)，gift_cards 表可复用 | P2 |
| 生日营销 | profile 补 birthday 字段+Klaviyo 生日流(自动发券) | P1 |
| 会员等级 | 积分已有，补等级(Silver/Gold: 消费门槛)分级权益(折扣/提前购/免邮) | P1 |
| 推荐有礼 | 双向奖励(推荐人$10/被邀人 85 折)， referral 表+防刷(同卡/同IP) | P1 |
| 沉睡唤醒 | 60/90 天未复购分层 EDM | P1 |

**补 DDL**
```sql
ALTER TABLE users ADD birthday DATE NULL, tier TINYINT DEFAULT 0;      -- P1
CREATE TABLE referrals(id, referrer_user_id, invited_email,            -- P1
  status(enum: pending/signed/first_order/rewarded), reward_type, rewarded_at);
CREATE TABLE subscriptions(id, user_id, stripe_subscription_id,        -- P2
  plan_enum(4w/6w/8w), status, next_billing_at, cancel_at_period_end);
```

### 2.5 营销与转化

| 缺失功能 | 说明 | 优先级 |
|---|---|---|
| **EXIT intent 弹窗** | 离开意图(鼠标移出+移动端回退)触发最后一搏 10% off | P0 |
| 首单优惠倒计时 | 弹窗领码后 15min 倒计时营造紧迫 | P1 |
| 闪购/每日特惠 | 24h 限时区块(首页)，到点自动上下架 | P1 |
| 满赠 | 满$45 送指甲锉(比满减更有溢价感)：cart 规则引擎补 gift 类型 | P1 |
| 邮件退订中心 | CAN-SPAM/GDPR 硬性要求：一键退订+偏好设置(只收上新/全退) | P0 |
|Coupon 门槛提示 | 购物车页"再买$X 可用此券" | P1 |
| UGC 激励闭环 | 画廊投稿被采用奖 100 分(已有积分基础，补规则) | P2 |

### 2.6 客服与售后工作台（几乎空白）

| 缺失功能 | 说明 | 优先级 |
|---|---|---|
| **工单系统** | 联系我们表单→工单(状态/指派/回复/关联订单)，客服工作台 | P0 |
| FAQ 中心 | 分类 FAQ(物流/退换/佩戴/尺码)前台+详情页锚点，减少 30%+ 咨询 | P0 |
| 客服快捷回复模板 | 后台维护常用回复语 | P1 |
| 订单时间线(内部) | 客服侧看订单全事件流(状态变更/退款/备注/邮件记录) | P0 |
| 退款原因分析 | 退货原因结构化统计→反哺产品(尺码不对占比?) | P1 |

**补 DDL**
```sql
CREATE TABLE tickets(id, ticket_no, user_id?, email, subject, category,
  order_no?, status(enum: open/pending/closed), assignee_admin_id, priority, created_at);
CREATE TABLE ticket_messages(id, ticket_id, sender(enum: user/admin/system),
  content, created_at);
CREATE TABLE order_timeline(id, order_id, event, detail json,          -- P0 内部时间线
  actor(enum: system/admin/user), created_at);
CREATE TABLE faqs(id, category, question, answer_md, sort_order, active);
```

### 2.7 数据看板补全

已有 GMV/转化等大盘，补运营日常必需视图：

| 看板 | 指标 | 用途 |
|---|---|---|
| 商品表现 | 每款：浏览/加购率/转化率/退货率/评分趋势 | 决定推流与下架 |
| 库存周转 | 售罄天数/周转率/滞销预警(60天未动) | 补货决策 |
| 用户资产 | 新老客占比/复购周期/LTV 分层/A 先权重 | 投放策略 |
| 营销 ROI | 各渠道/各码的核销与带来的 GMV | 停投无效码 |
| 履约监控 | 平均发货时长/物流时效达成率/退货率趋势 | 体验优化 |
| 财务简表 | 日销售额/退款率/Stripe 费用/毛利(含成本时) | 经营健康度 |

### 2.8 合规与信任（上线红线，原设计几乎空白）

| 项目 | 要求 | 优先级 |
|---|---|---|
| **GDPR** | Cookie 同意横幅(分区同意)、账户数据导出/删除自助、隐私政策(数据用途/保留期/DPO联系方式) | P0(欧盟流量) |
| **CAN-SPAM/邮件合规** | 每封营销邮件物理地址+一键退订(已补 2.5)；退订即时生效(≤3工作日) | P0 |
| CCPA(加州) | "Do Not Sell My Info"入口(虽不卖数据也要挂声明) | P0 |
| 退换货政策 | 明示期限(30天)、条件、流程；checkout 前可点阅(Shopify 标配) | P0 |
| 条款页 | ToS(用户协议/免责/知识产权) | P0 |
| 支付安全提示 | "Secure Checkout"徽章+SSL 说明 | P1 |
| 年龄声明 | 无年龄敏感商品可免 | — |
| 无障碍 | WCAG 基础(图片alt/键盘导航/对比度)——欧盟 EAA 2025 生效 | P1(欧盟) |

### 2.9 供应链与后台效率（P1-P2，人肉可撑一阵）

| 缺失功能 | 说明 | 优先级 |
|---|---|---|
| 采购单 | 向 OEM 下单跟踪(在途/到货/质检)，补"可用库存=现货+在途-安全" | P1 |
| 成本与毛利 | variant 补 cost 字段→看板算真实毛利 | P1 |
| 批量操作 | 批量改价/改分类/导出导入(CSV) | P1 |
| 打单发货流水线 | 仓库视角:待打面单→待拣货→待发货 列表+扫码校验 | P1 |
| 库存盘点 | 定期盘点差异调整(有流水) | P2 |

## 3. 补齐后的优先级汇总

### P0（MVP 必须带，缺了不能上线）
```
支付: PayPal + Apple/Google Pay + 先买后付(Klarna)
税务: Stripe Tax + 结账页税费拆分
合规: 隐私/条款/退换政策页 + Cookie 同意 + 邮件退订中心
商品: 尺码指南 + 变体图片
履约: 退货自助(RMA) + 物流跟踪页 + 订单时间线(内部)
客服: 工单系统 + FAQ 中心
转化: EXIT intent 弹窗 + 订单备注前台入口
```

### P1（上线后 1-2 月内）
```
换货、拆单发货、运费规则配置、到货通知、礼品卡、礼品选项
会员等级+生日+推荐有礼、闪购/满赠、地址校验
看板六视图、采购单+成本毛利、批量操作、打单流水线
```

### P2（3-6 月，战略功能）
```
订阅制月盒、储值钱包、多语言商品、UGC激励闭环、海关报关、无障碍、发票
```

## 4. 需要新增的数据表汇总（在详细设计 v1.1 基础上）

```
P0: variant_images / returns(RMA) / order_timeline / tickets /
    ticket_messages / faqs / cookie_consents(gdpr)
P1: shipments(拆单) / exchanges / shipping_rates / stock_notifications /
    gift_cards / gift_card_ledger / referrals / purchase_orders(采购) /
    product_translations(基准表)
P2: subscriptions / wallet(复用gift_cards结构)
ALTER: users.birthday/tier; variant.cost; orders.gift_message/gift_flag
```

**结论**：原 12+9 模块覆盖了标准电商骨架（约 60%），本次补齐 40+ 项缺口后达到 Shopify 成熟店水平。其中 **P0 的 15 项**（支付矩阵/合规/RMA/工单/尺码指南）直接影响"能不能上线"和"上线后死不死"，建议并入详细设计的 W1-W6 排期（P0 项预计增加 2 周工期，总 8 周）。
