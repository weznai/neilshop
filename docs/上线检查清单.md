## §1 基础设施（deploy.md §1 / 架构 v2 §7.0）

- [ ] **[BLOCK]** 服务器 4C8G+、系统盘 40G+，Debian 11/12 或 Ubuntu 22.04+，NTP 时间同步（`timedatectl` 确认）
- [ ] **[BLOCK]** Docker Engine ≥ 24 + Compose v2 插件（`docker compose version` 可用即 v2）
- [ ] **[BLOCK]** 域名 NS 托管至 Cloudflare（§7.0「入口交给 Cloudflare」：TLS/WAF/CC 防护由 CF 提供）
- [ ] **[BLOCK]** 防火墙/安全组仅开放 22（SSH）、80/443；**8000 与 3306 绝不对公网开放**（compose 中 api 仅绑 `127.0.0.1:8000`，mysql 不映射宿主端口）
- [ ] MySQL 8 就绪：compose 内置 `mysql:8.0`（utf8mb4 / utf8mb4_0900_ai_ci），或自管 8.0+（仅内网可达）
- [ ] 入口二选一就绪（deploy.md §2.1）：cloudflared Tunnel（推荐，零开放端口）或 Caddy 源站反代 + CF 橙云 Full (strict)

## §2 凭据与密钥（.env，永不入库 —— deploy.md §2 / .env.example）

生成方式统一 `openssl rand -hex N`，填写后 `docker compose config` 校验通过。

| 变量 | 生成/来源 | 未配置的降级行为 |
|---|---|---|
| `GM_JWT_SECRET` | `openssl rand -hex 32` | compose `${VAR:?}` **缺失直接拒绝启动**（部署侧强制）；本机直跑回落 config.py 的 dev 默认值（仅演示）。泄露 = 全员 token 可伪造；轮换 = 全员重新登录（deploy.md §6 属预期） |
| `GM_MYSQL_ROOT_PASSWORD` / `GM_MYSQL_PASSWORD` | `openssl rand -hex 16` | compose 缺失拒绝启动；`GM_DB` 由 compose 自动拼装，密码避开 URL 保留字符 |
| `GM_STRIPE_KEY`（+ `GM_STRIPE_WEBHOOK_SECRET`） | Stripe Dashboard（sk_live_ 开头） | 回落 **MockProvider**：支付走 `/api/payments/mock-pay`，**不能真实收款**（MVP §10.1 / server/app/services/payment_provider.py）；配了 key 但缺 stripe 包 → 告警后仍回落 mock |
| `GM_PAYPAL_CLIENT_ID` / `GM_PAYPAL_SECRET` / `GM_PAYPAL_BASE` | PayPal 应用（默认沙箱 base） | 未配置不启用 PayPal；缺 httpx 包回落 mock（MVP §19.1 支付矩阵） |
| Klarna | Stripe 侧开通 + `GM_STRIPE_KLARNA=1` | 未开启时支付方式列表不含 Klarna（选择优先级 stripe > paypal > mock，MVP §19.1） |
| 邮件发送（Resend 或 SMTP） | 上线前接入 | 当前 `emails.deliver()` 仅**日志投递不外发**（server/app/services/emails.py）——订单确认/发货/弃购三封召回（MVP §10.2）/运营日报（MVP §19.3）全部只落日志，**用户收不到任何邮件**；接 Resend/SMTP 前不得视为邮件链路可用 |
