# 指甲电商独立站 · 详细设计文档（v1.1）
> 配套《指甲电商独立站系统设计.md》概要版，本篇深入到 DDL、时序、接口报文、规则引擎级别，可直接指导开发。

---

## 1. 全局技术约定

| 项 | 约定 |
|---|---|
| 金额 | DB 存 `DECIMAL(10,2)`（报表可读）；**计算层一律转整数分**，杜绝浮点误差；Stripe 金额单位本就是分 |
| 时间 | 全部 `DATETIME(3)`，存 UTC，前端本地化展示 |
| ID | 主键 `BIGINT UNSIGNED AUTO_INCREMENT`；对外暴露一律用 `order_no`/`slug`，防枚举 |
| 软删 | 商品/文章用 `status` 字段，不物理删；订单永不删 |
| 枚举 | `TINYINT` + 应用层枚举映射（避免 MySQL ALTER ENUM 锁表） |
| 命名 | 表/字段 snake_case；表名复数（`orders` 避开保留字 `order`） |
| 审计 | 金额、库存、积分变动必须写流水表，禁止裸 UPDATE |

## 3. Redis 键空间设计

| Key | 类型 | TTL | 用途 |
|---|---|---|---|
| `cart:s:{sessionId}` | HASH `{variantId: qty}` | 7d | 游客购物车主体 |
| `cart:u:{userId}` | HASH | 30d | 登录用户购物车主体 |
| `stock:{variantId}` | STRING(int) | — | 可售库存（DB 库存 - 持有），Lua 原子扣 |
| `pd:detail:{slug}` | STRING(json) | 10min | 商品详情聚合缓存，更新时 DEL |
| `pd:list:{hash(params)}` | STRING(json) | 5min | 列表页缓存 |
| `rate:{ip}:{route}` | STRING INCR | 60s | 限流计数，>60 拒绝 |
| `session:{token}` | HASH `{userId, role}` | 30d 滑动 | 登录会话 |
| `search:hot` | ZSET | — | 搜索热词，ZRANGE 每小时衰减 |
| `lock:order:{orderNo}` | STRING NX | 10s | 回调/关单互斥锁 |

### 3.1 库存 Lua 脚本（防超卖核心）

```lua
-- hold_stock: KEYS[1]=stock:{id}, ARGV[1]=qty, ARGV[2]=orderNo
local stock = tonumber(redis.call('GET', KEYS[1]) or '-1')
if stock < 0 then return -2 end                    -- 键不存在，需从 DB 预热
if stock < tonumber(ARGV[1]) then return -1 end    -- 库存不足
redis.call('DECRBY', KEYS[1], ARGV[1])
redis.call('SADD', 'hold:' .. ARGV[2], KEYS[1] .. ':' .. ARGV[1])  -- 订单持有登记
return stock - tonumber(ARGV[1])

-- release_stock(orderNo): 遍历 hold:{orderNo} 逐条 INCRBY 回滚后 DEL
```

## 4. 核心业务时序

### 4.1 下单与支付（主链路）

```
① POST /api/checkout {items, address, code?, pointsToUse?}
② 服务端（全程不信任前端价格）:
   逐项查 variant 现价 → 计算行小计 → 校验折扣码(锁行) → 积分抵扣
   → 运费规则 → 税额(Stripe Tax API 试算) → grand_total
③ Redis Lua 预扣库存 → 失败立即返回 20002 库存不足
④ 事务落库: orders(status=0) + order_items + payments(待支付) + 积分冻结(points_ledger reason=4)
⑤ 创建 Stripe Checkout Session(success_url 带 order_no) → 返回跳转 URL
⑥ 用户付款 → Stripe → POST /api/webhooks/stripe (可能在用户跳回之前到达!)

⑦ Webhook 处理(payment_intent.succeeded):
   a. INSERT webhook_events(event_id) → 主键冲突 = 已处理, 直接 ACK 200
   b. SET lock:order:{orderNo} NX 10s（与超时关单互斥）
   c. DB 事务: payments→已成功, orders→PAID+paid_at, 点亮积分(交付后发放)
   d. Redis DEL cart:*（该用户/会话）、写 Klaviyo "已购买" 事件
   e. 发订单确认邮件(Resend) + 触发 SCA 加购转化埋点
⑧ checkout/success 页: 轮询 GET /api/orders/{orderNo} 展示状态（以 ⑦ 为准，不以此页判支付）

⑨ 兜底: 用户付了但 Webhook 丢失
   → success 页轮询时服务端主动 Stripe API 查 PaymentIntent 状态并补单
```

### 4.2 超时关单

```
每 60s 扫描: orders WHERE status=0 AND placed_at < NOW()-INTERVAL 30 MINUTE
逐单: SET lock NX → 反查 Stripe(防"已付未回调") → 未付则:
  status=8 canceled, reason=timeout
  → Redis release_stock(orderNo) 回滚持有
  → 解冻积分
```

### 4.3 购物车合并（游客 → 登录）

```
登录成功瞬间:
① 取 Redis cart:s:{sid} 与 cart:u:{uid}
② 两车都空 → 无操作；仅一边有 → 直接归位
③ 都有 → 按 variantId 合并, qty 相加, 单品上限 10, 车内总行数上限 50
④ DELETE cart:s:{sid}，写 cart:u:{uid}
⑤ MySQL carts 表 upsert 镜像(含 email, 供弃购扫描)
```

### 4.4 退款（部分/全额）

```
管理员发起 → 校验权限(见 §6 矩阵) → Stripe Refund API
→ Webhook charge.refunded → 事务:
   payments.refunded_amount 累加; 全额: orders→REFUNDED
   积分回冲(该单 earned 作废, 已用分返还)
   → 库存回补(可选, 商品未损) → 邮件通知
失败处理: Stripe 拒绝 → admin_log 记录 + 人工介入, 订单状态不变
```

### 4.5 评价资格

```
POST /api/reviews 前置校验:
  order_item.reviewed == 0
  AND 所属订单 status ∈ {DELIVERED, COMPLETED}
  AND delivered_at 在 30 天内
  AND variant 仍在售(允许下架商品评,只需 product 可见)
通过 → INSERT(status=0 待审) + order_items.reviewed=1
审核: 敏感词机审(自动通过率约 70%) + 人审队列 → 通过后异步重算商品 rating 冗余
```

### 4.6 弃购邮件流（BullMQ 延迟任务）

```
触发: carts 镜像表 updated_at 变化 → 重置 3 个 delayed job(1h/24h/48h)
执行条件: 未下单 AND abandoned_mails_sent < 3 AND recovery_token 有效
内容: ①提醒(无码) ②9折码 ABANDON10 ③85折码 LASTCALL20(标注最后提醒)
点击恢复: /cart?recover={token} → Redis 重建购物车 → 码自动预填
同一 email 30 天内全流程最多 3 封（Klaviyo 频控双保险）
```

## 5. API 详细规范

### 5.1 通用约定

- Base：`/api/v1`；内容类型 `application/json; charset=utf-8`
- 鉴权：`Authorization: Bearer <sessionToken>`（Redis session）
- 分页：`?page=1&pageSize=24`，响应统一 `{data, page, pageSize, total, totalPages}`
- 金额：请求响应统一 `"15.99"`（字符串保留 2 位）或分（int），全站二选一不混用
- 幂等：写操作带 `Idempotency-Key` 头（checkout 必带）

### 5.2 错误码表

| code | HTTP | 场景 |
|---|---|---|
| 10001 | 400 | 参数校验失败（返回 field 级明细） |
| 10002 | 401 | 未登录 / session 过期 |
| 10003 | 403 | 无权限（含 RBAC 拒绝） |
| 10004 | 429 | 触发限流 |
| 20001 | 404 | 商品不存在或已下架 |
| 20002 | 409 | 库存不足（返回各 variant 余量） |
| 20003 | 409 | 已售罄下架 |
| 30001 | 422 | 折扣码不存在 |
| 30002 | 422 | 折扣码过期/未开始 |
| 30003 | 422 | 未达最低金额（返回差额） |
| 30004 | 422 | 超过个人使用次数 / 非新客 |
| 31001 | 422 | 积分不足 / 超抵扣上限 |
| 40001 | 409 | 订单状态不允许该操作 |
| 40002 | 422 | 地址不可配送（无承运区） |
| 50001 | 502 | Stripe 调用失败 |
| 99999 | 500 | 未知错误（Sentry 上报） |
