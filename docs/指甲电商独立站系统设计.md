# 指甲电商独立站系统设计文档
> 项目代号：NailShop · 自研 DTC 独立站（穿戴甲/美甲周边）
> 版本：v1.0 · 定位：面向北美/欧洲市场的多语言、多币种 B2C 商城

---

## 1. 系统概述

### 1.1 业务目标
- 销售按压式穿戴甲（press-on nails）、磁吸睫毛及周边配件
- 支持高频上新（月 1–2 次）、SKU 多属性（甲型/长度/系列）
- 转化工具内建：折扣码、捆绑、新客礼、弃购挽回、会员积分
- 内容驱动：教程博客 + 买家秀 UGC，服务 SEO 与种草

### 1.2 核心角色
| 角色 | 说明 |
|---|---|
| 游客 | 浏览、加购、游客下单 |
| 会员 | 邮箱注册/Google 登录，积分、愿望单、订单追踪 |
| 运营/管理员 | 后台管理商品、订单、营销、内容 |
| KOC/达人（二期） | 专属推广码、佣金追踪 |

## 2. 技术架构

### 2.1 架构图（文字版）
```
[用户] → CDN(Cloudflare) → 前端 Next.js(SSR/ISR, Vercel)
                              │
                    ┌─────────┴──────────┐
                    │  API 层（Next.js API / NestJS） │
                    └─────────┬──────────┘
         ┌──────────┬──────────┼──────────┬───────────┐
     MySQL 8.0    Redis      对象存储     搜索服务     邮件服务
    (InnoDB 主数据) (缓存/会话) (S3/R2 图片) (Meilisearch) (Resend/SES)
        │
   ┌────┴────────────────────────────┐
   │  第三方：Stripe(支付) Klaviyo(邮件) │
   │  Shippo(物流) Algalytics(埋点)    │
   └─────────────────────────────────┘
```

### 2.2 技术选型
| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Next.js 14 (App Router) + TypeScript + Tailwind | SSR/ISR 利于 SEO，生态成熟 |
| 状态/数据 | React Query + Zustand | 服务端状态与购物车分离 |
| 后端 | Next.js API Routes 起步 → 可拆 NestJS | 先单体后拆分 |
| 数据库 | MySQL 8.0（InnoDB）+ Prisma ORM | utf8mb4 支持完善、JSON 类型和 CTE/窗口函数满足多属性 SKU 查询，运维生态成熟 |
| 缓存 | Redis | 会话、购物车、库存扣减、限流 |
| 搜索 | Meilisearch（自托管）| 毫秒级容错搜索，成本低于 Algolia |
| 图片 | Cloudflare R2 + Next/Image | 免出口流量费，自动 WebP/AVIF |
| 支付 | Stripe（Checkout + Elements）| 国际卡 + Apple/Google Pay |
| 邮件 | Resend + Klaviyo（营销流） | 事务邮件与营销分流 |
| 部署 | Vercel（前端）+ Fly.io/Railway（API+DB+Redis） | 免运维起步 |
| 监控 | Sentry + PostHog | 报错追踪 + 行为分析 |

## 4. 数据模型（核心表 · MySQL 8.0 / InnoDB）

> 约定：字符集 `utf8mb4`（支持表情符号，买家秀必备）；金额一律 `DECIMAL(10,2)`；枚举用 `TINYINT` + 应用层映射（避免 ALTER 锁表）；JSON 字段用 MySQL 原生 `JSON` 类型（可用 `->>` 提取并建虚拟列索引）。

```sql
-- 用户
user(id, email, password_hash, name, role, points, created_at)
user_address(id, user_id, full_name, line1, line2, city, state, zip, country, phone, is_default)

-- 商品
product(id, slug, title, subtitle, description_md, category_id, status,
        compare_at_price, price_min, price_max, hero_image, images json,
        is_new, is_best_seller, published_at)
variant(id, product_id, sku, option1_name, option1_value,      -- 甲型: Short Almond
        option2_name, option2_value,                           -- 长度/颜色
        price, stock, weight_gram, is_active)
category(id, parent_id, slug, name, sort_order)                -- 树形分类
collection(id, slug, title, rule_json)  -- 智能集合: {tags:["new"], price_lt: 20}

-- 购物与订单
cart(id, user_id?, session_id, items json, updated_at)
order(id, order_no, user_id?, email, status, currency,
      subtotal, discount_total, shipping_fee, tax, grand_total,
      shipping_address json, placed_at, paid_at, shipped_at, tracking_no)
order_item(id, order_id, variant_id, title_snapshot, image, qty, unit_price, subtotal)
payment(id, order_id, stripe_payment_intent, amount, status, raw_event json)

-- 营销
discount_code(id, code, type(enum: percent/fixed/freeship), value,
              min_subtotal, usage_limit, per_user_limit, used_count,
              starts_at, ends_at, is_stacked)
bundle(id, title, variant_ids json, bundle_price, active)

-- 评价与内容
review(id, product_id, user_id, order_item_id, rating, content,
       images json, status(enum: pending/approved/rejected), created_at)
article(id, slug, title, cover, content_md, author, tags json, published_at)

-- 积分与日志
points_ledger(id, user_id, change, reason, ref_id, created_at)
admin_log(id, admin_id, action, entity, entity_id, diff_json, created_at)
```

### 4.1 订单状态机
```
PENDING_PAYMENT → PAID → FULFILLING → SHIPPED → DELIVERED → COMPLETED
      │              │                              │
      └─ CANCELED    └──────── REFUNDED ←───────────┘（部分/全额）
```
状态流转由事件驱动（Stripe Webhook / 物流 Webhook / 定时任务超时关单）。

## 6. 关键接口设计（REST 示例）

```
GET  /api/products?category=nails&shape=almond&sort=new&page=1
GET  /api/products/:slug                    # 含变体/评价摘要/相关推荐
POST /api/cart/items                        {variantId, qty}
PATCH /api/cart/items/:id                   {qty}
POST /api/cart/apply-code                   {code} → 返回试算结果
POST /api/checkout                          创建订单 + Stripe PaymentIntent
POST /api/webhooks/stripe                   支付回调（验签+幂等）
GET  /api/orders/:orderNo/track
POST /api/reviews                           {orderItemId, rating, content}
POST /api/newsletter/subscribe              Klaviyo 同步
```

**安全要点**：Stripe Webhook 验签 + 事件 ID 幂等表；库存扣减用 Redis 预扣 + DB 事务补偿；接口限流（IP 60/min）；价格只在服务端计算。

## 7. 营销与增长系统

| 能力 | 实现方式 |
|---|---|
| 新客礼包 | 首访弹窗留邮箱 → Klaviyo 发 WELCOME20 码 |
| 折扣码 | 后台批量生成、限时限次、是否可叠加规则 |
| 捆绑价 | bundle 表 + 详情页"经常一起买"组件 |
| 弃购挽回 | 购物车 1h/24h/48h 未下单 → Klaviyo 三封序列 |
| 积分体系 | points_ledger 流水，下单奖励与评价奖励防刷（人工审核阈值） |
| 倒计时/库存角标 | 组件化，后台开关，防"虚假紧迫"合规风险 |
| 邮件营销 | 上新通知、弃购、订单事务邮件（Resend）、营销 EDM（Klaviyo） |

## 8. 非功能需求

| 维度 | 目标 |
|---|---|
| 性能 | 首页/详情 LCP < 2.5s；列表接口 P95 < 300ms（Redis 缓存） |
| SEO | SSR + 结构化数据（Product/Offer/Review）+ sitemap 自动生成 |
| 可用性 | 核心链路 99.9%；MySQL 每日全备（mysqldump/XtraBackup）+ binlog 增量实现时间点恢复（PITR） |
| 安全 | HTTPS 全站、CSP、PCI 由 Stripe 托管页承担、GDPR（Cookie 同意 + 数据删除接口） |
| 可扩展 | 模块化单体起步，预留拆分边界；图片走 CDN 无状态扩容 |

## 10. 风险与对策
- **支付合规**：全程用 Stripe 托管组件，不落卡数据
- **库存超卖**：Redis 预扣 + DB 乐观锁 + 超时释放
- **爬虫/薅羊毛**：Cloudflare 防护 + 折扣码风控（同 IP/卡指纹限领）
- **物流异常**：Shippo 自动面单 + 物流 Webhook 更新状态 + 客服工单入口
