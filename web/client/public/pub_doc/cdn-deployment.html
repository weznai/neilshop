1概述：CDN 是什么，为什么用

CDN（Content Delivery Network，内容分发网络）是一组分布在全球各地的边缘服务器（PoP，Point of Presence）。用户访问网站时，DNS 通过 Anycast 技术把请求调度到距离最近、延迟最低的节点：静态内容直接从边缘返回（不再触碰源站），动态请求由边缘经优化路径回源。Cloudflare 在全球 330+ 城市部署节点（以官方数据为准），免费计划即提供 CDN + WAF + 无限量 DDoS 防护。

1.3 收益量化（单机阶段）

  • 源站压力：静态资源全走 CDN 后，回源只剩 API 动态调用；单台 4C8G 可承载日 PV 10-30 万 / 日订单 3000-8000（架构 v2 §7.0 容量天花板经验值）；
  • 延迟：边缘命中 TTFB 通常 <50ms；首屏 LCP <2.5s（4G）目标依赖 Hero 图 AVIF + CDN 分发；
  • 成本：免费计划覆盖核心能力，单机全套（服务器 + CDN + 备份）预算 $100/月内；
  • 可用性：入口高可用交给云；源站整机宕机时 CF 仍服务缓存内容与兜底品牌页（§20）。

为什么选 Cloudflare 而非传统 CDN：① 免费计划即含 WAF 与无限 DDoS 防护；② 与 Tunnel / R2 / Origin CA / Access 一体化，无需另购证书与专线；③ 本项目目标市场为海外 DTC（美/欧），CF 边缘节点覆盖正好匹配。国内用户访问 CF 免费节点速度一般——本站主要面向海外买家，不受影响。

2.3 缓存层级（三级）

[浏览器] ──miss──► [CF 边缘 PoP(就近)] ──miss──► [上层 PoP/Tiered Cache] ──miss──► [源站] ▲ ▲ ▲ Browser TTL Edge TTL 上层缓存兜底 (Cache-Control) (Cache Rules/源站头) (Smart Tiered Cache,免费开启) 命中率逐级兜底: 浏览器 60-90% → 边缘 85%+ → Tiered → 源站只承受长尾

三级缓存的 TTL 各自独立：Browser TTL 由 Cache-Control: max-age 控制（用户本地），Edge TTL 由 Cache Rules 或源站 s-maxage 控制（CF 边缘），互不干扰。发布新版后浏览器缓存由 hash 文件名天然失效（§19.1）。

4.1 存量站点割接 Runbook（低风险切换 7 步）

  1. 预检（割接前 1 天）
    确认源站 nginx 80/443 正常（curl -sI https://zoo1.cn/api/health）；CF 添加站点并导入 DNS 记录（§5），此时仅灰云。此步不影响线上。
  2. 降 TTL
    在 dnspod 把 @/www 的 A 记录 TTL 降到 300 秒，加快后续切换收敛与回滚。
  3. 择低峰窗口
    选流量谷段（看访问日志，一般凌晨），预估影响窗口 ≤30 分钟（仅 DNS 收敛期间可能波动）。
  4. 改 NS
    到域名注册商（腾讯云控制台）把 NS 从 dnspod 改为 CF 分配的两个 NS。生效 5 分钟～24 小时，可用 dig NS zoo1.cn +short 轮询确认。
  5. 灰云验证
    NS 生效后记录仍是灰云（DNS only），流量仍直连源站——验证解析正确、业务无异常。
  6. 开橙云
    确认 SSL 模式已设 Full (strict)（§9）后，把 A 记录切换为橙云。验证：curl -sI https://zoo1.cn/ 出现 cf-ray / server: cloudflare。
  7. 观察 24h + 回滚预案
    关注 Security Events 误拦、缓存状态、5xx 比例。异常回滚：CF 记录改灰云（秒级）或 NS 改回 dnspod（≤TTL 300s 收敛）。

割接后必做：① Stripe webhook 地址仍为 https://zoo1.cn/api/payments/webhook（域名不变无需改，但需确认未被 WAF 误拦，§23）；② 源站防火墙收紧为只放行 CF 回源 IP 段（方案 B）或关停 80/443（方案 A），防直连绕过 CF；③ 源站 IP 已暴露过，割接稳定后评估换 IP（Tunnel 方案可彻底规避）。

5第一步：域名接入 Cloudflare

  1. 添加站点
    CF 控制台 → Add a domain → 输入裸域 zoo1.cn → 选 Free 计划。CF 自动扫描 dnspod 侧现有记录并导入。
  2. 修改注册商 NS
    CF 分配两个 NS（形如 xxx.ns.cloudflare.com），到腾讯云控制台把域名 NS 改为这两个地址。站点页显示 Active 即生效。验证： 
    dig NS zoo1.cn +short          # 应返回两个 *.ns.cloudflare.com
dig A zoo1.cn +short @1.1.1.1  # 解析验证
  3. 配置 DNS 记录
    按下表（Proxy 状态决定是否走 CDN）：
    类型名称内容Proxy用途
    A / AAAA@（裸域）源站公网 IP橙云 ON主站（方案 B 必须；方案 A 可仅留 Tunnel CNAME）
    A / AAAAwww同上橙云 ONwww 访问
    CNAME<tunnel-id>.cfargotunnel.com—橙云 ON方案 A：由 Tunnel 的 Public Hostname 自动创建
    CNAMEcdnR2 自定义域（§19）橙云 ON可选：图片走 R2 + CDN
    CNAMEstaging测试环境源站灰云/橙云+Access预发布环境（§15 亦可加门禁）
    MX / TXT@邮件服务器 / SPF·DKIM自动灰云邮件记录不可代理（CF 强制 DNS only），照常导入即可

    橙云 vs 灰云：橙云（Proxied）= 流量经 CF CDN/WAF，源站 IP 隐藏；灰云（DNS only）= 纯解析直连。对外 Web 记录一律橙云；MX/TXT 等邮件记录只能灰云。排障临时切灰云会暴露源站 IP，用完必须改回。

  4. 开启全站 HTTPS 跳转
    CF → SSL/TLS → Edge Certificates → 打开 Always Use HTTPS。
  5. （推荐）开启 DNSSEC
    CF → DNS → Settings → Enable DNSSEC，把给出的 DS 记录（Key Tag/Algorithm/Digest）填到注册商的 DNSSEC 设置。防 DNS 劫持/中间人污染。生效后 dig DS zoo1.cn +short 验证；未生效前不要重复开启。

5.1 进阶 DNS 知识

主题要点
CNAME Flattening根域（裸域）协议上不允许 CNAME，CF 自动将其「扁平化」为 A 记录返回——因此裸域也能安全指向 Tunnel/R2 的 CNAME 目标，注册商 DNS 常无此能力
TTL 策略橙云记录对外通告 TTL 固定 300 秒（Auto）；灰云记录自定义 TTL——割接前降 TTL、稳定后调大减少查询延迟
子域规划主站 zoo1.cn / www；图片 cdn.zoo1.cn（R2）；预发 staging.zoo1.cn。注意 Universal SSL 免费证书只覆盖裸域+一级子域，更深层级（a.b.zoo1.cn）需付费 ACM 或改用一级子域
泛解析* 记录可橙云，但配合 Universal SSL 同样只覆盖一级；避免依赖深层泛子域

6第二步 · 方案 A：cloudflared Tunnel（推荐，零开放端口）

原理：源站运行 cloudflared 守护进程，主动向 CF 建立出站加密隧道（4 条 HA 连接）；公网流量经边缘节点逆行进隧道到达内网服务。源站不需要任何入站端口，防火墙只留 22。

6.1 部署五步（Dashboard Token 方式）

  1. 创建 Tunnel
    CF → Zero Trust → Networks → Tunnels → Create a tunnel → Cloudflared 类型 → 命名 glowmag-prod → 记下 Token。
  2. compose 追加 tunnel 服务
    仓库根 docker-compose.yml 末尾追加（与 api 同网络 glowmag-net，容器名直连不经过宿主端口）： 
      tunnel:
    image: cloudflare/cloudflared:latest
    container_name: glowmag-tunnel
    restart: unless-stopped
    command: tunnel --no-autoupdate run --token ${CF_TUNNEL_TOKEN:-}
    networks: [glowmag-net]
  3. .env 注入 Token
    CF_TUNNEL_TOKEN=eyJhIjoixxxx...（密钥永不入库，与 GM_JWT_SECRET 同纪律）。
  4. 配置 Public Hostname
    Tunnel 详情页 → Public Hostname → Add：
    字段值说明
    Subdomain / Domainzoo1.cn（及一条 www）CF 自动建 CNAME 记录（橙云）
    TypeHTTP隧道内段容器内网明文即可（外段仍 HTTPS）
    URLapi:8000容器名直连，勿写 127.0.0.1（tunnel 容器内 127.0.0.1 是它自己）
  5. 启动并验证 
    cd /opt/nailshop && docker compose up -d
docker compose logs -f tunnel        # "Registered tunnel connection" ×4 即成功
curl -sI https://zoo1.cn/api/health  # 200 + cf-ray

6.2 备选：config.yml 本地配置方式（不入 Dashboard）

适合配置进 git 做版本管理。登录机器执行 cloudflared tunnel login 取证书，再写配置：

# /etc/cloudflared/config.yml
tunnel: glowmag-prod
credentials-file: /etc/cloudflared/glowmag-prod.json
ingress:
  - hostname: zoo1.cn
    service: http://api:8000        # 或本机部署时 http://localhost:8000
  - hostname: cdn.zoo1.cn
    service: https://<ACCOUNT>.r2.cloudflarestorage.com   # 直接把 R2 挂在隧道后也可
  - service: http_status:404        # 兜底必须放最后

系统服务：cloudflared service install；Docker 方式把该文件挂进容器并去掉 --token 参数。两种方式二选一（Token 方式配置存 CF 侧，改后即生效；yml 方式配置随代码走）。

6.3 高可用与运维要点

  • 多副本：同一 Token 起第二个 cloudflared 实例（另一台机或同机容器），CF 自动在多连接间负载均衡——单进程挂不影响入口；
  • 指标：容器内 localhost:20241/metrics 暴露 Prometheus 指标（连接数/重连次数），可接入 §21 监控；
  • 排障：docker compose logs tunnel 看重连日志；Tunnel 页面看连接数（正常 4）；docker compose restart tunnel 处理偶发断连；
  • 能力边界：支持 WebSocket（站内若加实时功能无碍）；大文件上传受 CF 代理 100MB 请求体限制（§23 速查表）。

7第二步 · 方案 B：源站反代（Caddy）+ 橙云 Full (strict)

原理：宿主机装 Caddy 监听 80/443 做 HTTPS 反代，CF 橙云回源到 Caddy。适用：需保留直连 IP 冗余通道、源站与 CF 网络质量需调优等场景。

  1. 安装 Caddy（Debian/Ubuntu 官方源），Caddyfile 反代到 api： 
    zoo1.cn {
    reverse_proxy 127.0.0.1:8000
}
    Caddy 默认自动申请公共证书；生产建议改用 Origin CA 证书（15 年有效，仅 CF 信任）。
  2. 签发 Origin CA 证书（6 步）
    ① CF → SSL/TLS → Origin Server → Create Certificate；② 保持默认（RSA 2048 / 15 年 / 覆盖 *.zoo1.cn 与 zoo1.cn）；③ 复制证书与私钥分别存为 /etc/ssl/caddy/origin-cert.pem、origin-key.pem（chmod 600）；④ Caddyfile 改 tls /etc/ssl/caddy/origin-cert.pem /etc/ssl/caddy/origin-key.pem；⑤ systemctl reload caddy；⑥ 验证回源握手： 
    openssl s_client -connect 127.0.0.1:443 -servername zoo1.cn \
  | openssl x509 -noout -subject -dates   # 应显示 Origin CA 签发与长期有效
  3. CF 侧 SSL 模式：设为 Full (strict)（回源验证证书）。禁止 Flexible（回源走 HTTP 且引发重定向循环）。
  4. 防火墙收紧（强烈建议）：80/443 入站规则只放行 CF 回源 IP 段，其余直连扫描全部拒绝——彻底堵住「知道源站 IP 绕过 CF」的旁路。
  5. 验证：curl -sI https://zoo1.cn/ 期望 200，server: 头已被 CF 隐藏。

10缓存机制原理（先懂原理，再配规则）

10.1 什么会被缓存、什么不会

判定项默认行为
请求方法仅 GET/HEAD 可能缓存；POST/PUT/DELETE 永不缓存
静态扩展名js/css/png/jpg/webp/avif/svg/gif/ico/woff/woff2/pdf/mp4 等默认缓存（无需配置）
HTML / API 响应默认不缓存（DYNAMIC），要缓存须 Cache Rules 显式开启
带 Authorization 头的请求默认不缓存（防登录态串号）
带 Set-Cookie 的响应默认不缓存
Cache-Control: private / no-store尊重源站，不缓存
查询字符串默认整串参与缓存键：?w=400 与 ?w=800 是两份缓存

10.2 Cache-Control 指令语义速查

指令作用层含义
max-age=N浏览器 + 共享缓存N 秒内可直接用副本不再验证
s-maxage=N共享缓存（CDN）覆盖 max-age，仅对 CDN 生效——给 CF 的专属指令
public / private共享缓存private 表示含个人数据，CDN 不得缓存
no-cache双层可存副本但每次使用前须协商验证（ETag）
no-store双层彻底不存（API 敏感响应用）
immutable浏览器副本期内连协商验证都不发——配合 hash 文件名使用
stale-while-revalidate=N双层过期后 N 秒内先返回旧副本、后台异步刷新（用户零等待）
stale-if-error=N双层源站 5xx/超时时，N 秒内继续服务过期副本——源站故障时的保命指令

10.3 TTL 判定优先级（谁说了算）

1. Cache Rules 显式 Edge TTL ← 最高优先级(§11 规则里设的) 2. 源站 Cache-Control (s-maxage > max-age > Expires) 3. 状态码默认值(源站无任何头时): 200 / 206 / 301 → 120 分钟 302 / 303 → 20 分钟 404 / 410 → 3 分钟 其余状态码 → 不缓存 4. 以上均无法判定 → 动态请求不缓存(DYNAMIC)

10.4 缓存键组成

默认缓存键 = 主机名 + 路径 + 完整查询串。高级定制（按 Cookie/Header 分键、忽略指定参数）部分属企业功能——本项目用「查询参数天然分键」即可满足图片变体需求（?w=/?q= 各自缓存，不串）。注意：不同 Header（如 Accept-Language）默认不参与键，切勿让同一 URL 按请求头返回不同内容，否则会串缓存。

10.5 CORS 与缓存

跨域响应（带 Access-Control-Allow-Origin）一旦被缓存，会被复用给其他来源的请求导致 CORS 报错。纪律：带 CORS 头的 API 一律 Bypass（§11 规则 1 已覆盖 /api/*）；确需缓存的跨域静态资源用「来源白名单 + 统一 ACAO 头」固定响应。

15.2 与应用登录的关系

层认证方式挡住什么
CF Access（边缘）邮箱 OTP（一人一码，可开 2FA）未授权者根本接触不到后台登录页/接口——爆破面消失

16.3 应用侧取用（FastAPI 示例）

def client_ip(request: Request) -> str:
    """经 CF 代理后的访客真实 IP：优先 CF 头，兜底 XFF 第一跳。"""
    cf = request.headers.get("cf-connecting-ip")
    if cf:
        return cf
    xff = request.headers.get("x-forwarded-for", "")
    return xff.split(",")[0].strip() or (request.client.host if request.client else "unknown")

# 用途: 登录风控 / 评价提交防刷 / AI 客服限流等一律走此函数,
# 切勿直接用 request.client.host(那是 CF/反代的 IP)

export default {
  async fetch(request) {
    const upstream = await fetch(request);
    if (upstream.status >= 521 && upstream.status <= 526) {
      return new Response(FALLBACK_HTML, {
        status: 503,
        headers: { "content-type": "text/html; charset=utf-8",
                   "retry-after": "300" },
      });
    }
    return upstream;   // 正常响应原样放行
  },
};

<meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1">
<title>GLOWMAG — Be right back</title></head>

17.2 其他常用姿势

  • 安全响应头注入：给 HTML 加 X-Content-Type-Options / Referrer-Policy / X-Frame-Options（边缘做的好处是改配置即全站生效）；
  • 地域重定向：request.cf.country 判断，非目标市场把营销活动页 302 到对应语言版；
  • A/B 分流：按 Cookie 哈希把 5%/25% 流量指向新落地页（配合灰度发布）；
  • Workers KV（免费 10 万读/天）：边缘键值存储，存特性开关/简单配置，全球毫秒级读取；
  • Snippets（Rules → Snippets）：无需写完整 Worker 的小段改写，轻量场景优先用。

纪律：Worker 里 fetch(request) 会绕过边缘缓存直达源站——兜底页 Worker 只在源站故障时改写响应，正常流量务必原样返回 upstream；确需缓存参与时用 caches.default.match/put 显式处理，避免命中率塌方。

缓存命中率低（<60%）Analytics 按 URL 看未命中构成查询参数变体过多 → 收敛参数档位（§19.4）；HTML/动态占比高 → 属正常
应用限流误伤大量用户应用日志里来源 IP 是否全是 CF 段未恢复真实 IP → §16 配 real_ip / CF-Connecting-IP，按真实 IP 计数

跨域接口偶发 CORS 报错报错响应的 cf-cache-status带 ACAO 头的响应被缓存复用给其他来源 → 该接口 Bypass（§10.5）
大文件/图集上传失败失败请求大小是否 >100MBCF 代理请求体上限 100MB（免费/Pro）→ 超大文件直传 R2 预签名 URL，不 经代理
慢接口偶发 524接口耗时是否接近/超 100s回源响应超时上限 → 改异步任务（提交返回任务号 + 轮询），别让 HTTP 请求挂满 100s
R2 上传失败（rclone）rclone lsd r2: 测连通Token 过期/权限缺失 → R2 控制台重发 Access Key；endpoint 账号 ID 填错 → §19.3
灰云切换后忘改回DNS 面板 Proxy 列全橙云源站 IP 暴露风险 → 立即恢复橙云；若 IP 已泄露考虑换 IP（Tunnel 方案无此忧）
DNS 改了没生效dig NS zoo1.cn +short @8.8.8.8本地/递归 DNS 缓存 → 等 TTL（橙云 300s）；注册商 NS 未改成功 → 核对 §5 步骤 2

24上线检查清单（CDN 部分）

对应《上线检查清单.md》§1/§2 的 CDN 相关项，逐项勾选：

  • [BLOCK] 域名 NS 已托管至 Cloudflare，站点状态 Active（dig NS 验证）
  • [BLOCK] 入口二选一就绪：cloudflared Tunnel（推荐，零开放端口）或 Caddy 反代 + 橙云 Full (strict)
  • [BLOCK] 防火墙/安全组仅开放 22（SSH）、80/443（仅方案 B，且限 CF 回源段）；8000 与 3306 未对公网开放
  • [BLOCK] SSL/TLS = Full (strict)；Always Use HTTPS 开启；Min TLS 1.2；回源证书就位（Origin CA 或有效公共证书）
  • Cache Rules 四条基线规则就位（api-bypass / admin-bypass / assets-long / images-cache），cf-cache-status 验证符合预期（§11.3）
  • Smart Tiered Cache 已开启（§11.6）
  • 源站响应头按 §11.2 落地（assets immutable / HTML SWR / API no-store）
  • WAF 托管规则 + Bot Fight Mode 开启；自定义规则按「先 Log 后拦截」流程上线（§13）
  • Rate Limiting 全站防扫规则生效（§14）
  • 真实 IP 已恢复：nginx real_ip / 应用 CF-Connecting-IP（§16），限流风控不再按 CF IP 计数
  • /admin 已加 CF Access 门禁（§15，可选但强烈推荐）
  • Stripe webhook 地址 https://zoo1.cn/api/payments/webhook 在 Stripe 侧登记且未被 WAF 误拦（§23）
  • 兜底方案就位：HTML 短缓存 + stale-if-error + （可选）Worker 兜底页（§17/§20）
  • 性能开关确认：HTTP/3、Early Hints、Brotli 开；Rocket Loader 关（§12）
  • 外部拨测四链路（首页/加购/搜索/checkout）1 min 频率就绪，覆盖美/欧；拨测 UA 加 WAF 白名单
  • 割接 Runbook（§4.1）演练过一次，回滚路径（灰云/NS 回切）验证可用
  • 缓存命中率基线记录（上线首日 Analytics 留档，目标 >85%）
  • CF_TUNNEL_TOKEN（方案 A）已入 .env，未提交仓库、未进镜像
  • DNSSEC 已开启且 DS 记录在注册商生效（可选，推荐）
